# BackPropergation 修正記録

2026年11月17日。レポート提出後の見直しで見つかった不具合3点と綴り2か所を `src/backprop.c` で修正した。

- 修正したファイル：`src/backprop.c` のみ
- 修正前のファイル：`src/backprop.c.orig`（同じフォルダに保存）
- 提出物：提出用アーカイブとレポート（`*.tex`、`img/`、`result/`）には手を入れていない

## 修正1：隠れ層の誤差項が常に0番目のノードの出力を使っていた

場所：`bp_backward`、隠れ層の delta を計算するループ

修正前

```c
cur->nodes[i].delta = sum_delta * cur->nodes[i].funcs->derivative(cur->nodes->result);
```

修正後

```c
cur->nodes[i].delta = sum_delta * cur->nodes[i].funcs->derivative(cur->nodes[i].result);
```

`cur->nodes->result` は `cur->nodes[0].result` と同じ意味になる。そのため、層内のどのノードの誤差項にも、0番目のノードの出力から求めた導関数値が掛かっていた。ノードごとの出力 `cur->nodes[i].result` を使うのが正しい。

## 修正2：出力バッファの確保サイズ不足（領域外書き込み）

場所：`calculate_output`

修正前

```c
double80 *output      = malloc(output_layer->size * sizeof(double));
```

修正後

```c
double80 *output      = malloc(output_layer->size * sizeof(*output));
if (!output)
    return NULL;
```

`double80` は `long double`（x86-64 の gcc では 16 バイト）だが、`sizeof(double)`（8 バイト）で確保していた。出力ノード1個の場合、8 バイトの領域に 16 バイトを書き込む。`sizeof(*output)` にして型と確保サイズが食い違わないようにし、確保失敗時の NULL チェックも足した。

## 修正3：乱数シードの初期化判定が逆だった

場所：`rand_double`

修正前

```c
if (unlinkey(!init_rand)) {
    fprintf(stderr, "rand_double: init_rand is NULL, initializing with SEED %d\n", SEED);
    init_rand(SEED);  // 乱数初期化
    init_rand = NULL; // 初期化後は NULL に設定
}
```

修正後

```c
if (unlinkey(init_rand)) {
    init_rand(SEED);  // 初回呼び出し時のみ SEED で乱数を初期化
    init_rand = NULL; // 初期化後は NULL に設定
}
```

`init_rand` は最初 `init_genrand` を指しているので、`!init_rand` は常に偽になり、この分岐には一度も入らなかった。結果として `SEED` は使われず、MT.h 側の既定シード（5489）で動いていた。仮に分岐に入った場合は NULL の関数ポインタを呼ぶことになる。判定を反転し、初回呼び出し時に一度だけ `SEED` で初期化するようにした。内容が実態と合わなくなる stderr へのメッセージは削除した。

## 確認したこと

確認はフォルダの外に複製したコピーで行った。`main.c` の `LOOP` は複製側だけ短くしており、フォルダ内の `main.c` は変更していない。

| 確認内容 | 修正前 | 修正後 |
| --- | --- | --- |
| AddressSanitizer（LOOP=20,000） | `calculate_output` で heap-buffer-overflow を検出（8バイト領域に16バイト書き込み） | 検出なし（UBSan 併用でも検出なし） |
| コンパイル（gcc -Wall -O3） | 通る | 通る |

修正1の効果を切り分けるため、乱数シードを揃え（既定シード 5489）、修正2だけを両方に入れた状態で、修正1の有無だけを変えて 5,000,000 回学習させた。直近 50,000 回の RMSE の平均は次のとおり。

| 進行度 | 修正1なし | 修正1あり |
| --- | --- | --- |
| 20% | 0.2365 | 0.3112 |
| 40% | 0.1918 | 0.1985 |
| 60% | 0.2384 | 0.1295 |
| 80% | 0.2109 | 0.0742 |
| 100% | 0.0742 | 0.0463 |

修正ありの方が後半で安定して下がり、最終値も小さい。ただしシード1通り・1回の実行だけの結果なので、傾向の確認にとどまる。

## 修正4：綴りの修正（動作は変わらない）

- マクロ名 `unlinkey` を `unlikely` に直した（定義1か所、使用1か所）
- コメント `auto derivateve` を `auto derivative` に直した

修正後に gcc -Wall -O3 でコンパイルが通ることを確認した。

## レポートへの影響

- レポートの実験結果（`img/`、`result/`）は修正前のコードで出したものである。修正後のコードで再実行すると、数値とグラフは一致しない
- 理由は2つ。修正1で学習の挙動が変わること、修正3で乱数シードが 5489 から 0 に変わること
- レポートの数値を再現したい場合は `src/backprop.c.orig` か、提出用アーカイブを使う
