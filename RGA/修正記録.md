# RGA 修正記録

2026年11月17日。レポート提出後の見直しで3点を修正した。いずれも、レポートの実験で使った条件での結果は変わらない。

- 修正したファイル：`src/main.c`、`src/types.h`、`src/rga.c`
- 修正前のファイル：`src/main.c.orig`、`src/types.h.orig`、`src/rga.c.orig`（同じフォルダに保存。提出用アーカイブの内容と同一）
- レポートと提出用アーカイブには手を入れていない

## 修正1：個体数が3未満でも処理が続いていた

場所：`src/main.c`、引数チェック

修正前

```c
if (individuals < 3)
    PR_ERR("Error: Number of individuals must be at least 3.");
```

修正後

```c
if (individuals < 3) {
    PR_ERR("Error: Number of individuals must be at least 3.");
    return EXIT_FAILURE;
}
```

エラーメッセージを出すだけで終了していなかった。個体数1で実行すると、`update_rga` が上位2個体を取り出すところで、存在しない2番目の個体を読み込む（領域外読み込み）。メッセージどおり、3未満なら終了するようにした。個体数2は修正前は動いていたが、メッセージの内容に合わせて同じく拒否する。

## 修正2：`bool` を使うのに `<stdbool.h>` を読み込んでいなかった

場所：`src/types.h`

```c
#include <stdbool.h>
```

を追加した。`bool` / `true` / `false` をヘッダなしで使えるのは C23 のキーワードに対応したコンパイラ（GCC 13 以降）だけで、GCC 11 ではコンパイルエラーになっていた。追加後は GCC 11 でも通る。

## 修正3：毎世代の余分なソートをなくした

場所：`src/rga.c`、`update_rga` と `init_populations`

`update_rga` は最後に個体をソートしているのに、次の呼び出しの冒頭でも無条件にソートしていた。`sorted` フラグを見て、ソート済みなら冒頭のソートを省くようにした。あわせて、`init_populations` でフラグを `false` に戻すようにした。

```c
// update_rga の冒頭
if (!self->sorted)
    sort_population(self);
```

## 確認したこと

確認はフォルダの外に複製したコピーで行った。`main.c` の `LOOP` は複製側だけ短くしている。

| 確認内容 | 修正前 | 修正後 |
| --- | --- | --- |
| 個体数1で実行（AddressSanitizer） | `update_rga` で heap-buffer-overflow（読み込み）を検出 | エラーメッセージを出して終了 |
| 個体数2で実行 | エラーメッセージを出したうえで実行される | エラーメッセージを出して終了 |
| 個体数3、100で実行（AddressSanitizer + UBSan） | 検出なし | 検出なし |
| GCC 11.4 でのコンパイル（-std=c2x） | エラー（`bool` が未定義） | 通る |

修正前後で結果が変わらないことを、20,000世代の実行で出力される `fitness.csv` の一致で確認した。

| 個体数 / 交叉率 / 突然変異率 | `fitness.csv` | 実行時間（修正前 → 修正後） |
| --- | --- | --- |
| 100 / 0.5 / 0.05 | 完全に一致 | 2.21秒 → 2.15秒 |
| 200 / 0.8 / 0.01 | 完全に一致 | 3.16秒 → 3.12秒 |

実行時間の差は2〜3%で、1回ずつの計測なので誤差の範囲を出ない。ソートの省略で遅くはなっていない、という程度の確認である。
